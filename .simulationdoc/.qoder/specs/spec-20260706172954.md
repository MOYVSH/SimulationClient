# Unity 模拟经营项目开发计划

## Context

项目基于 `unity_simulation_design_v1.md` 技术设计文档，目标是实现一款参考 *Against the Storm*、*Timberborn*、*Factorio* 的斜 45° 视角模拟经营游戏。当前工作目录为纯净空地（仅含设计文档），需要从 0 开始建立 Unity 项目并实现全部系统。

本计划将设计文档中的 6 个宏观阶段拆解为可执行、可验证的具体任务，明确每个任务的产出、依赖和验收标准，使开发可以按阶段推进并在早期得到可运行的原型。

## 目标与约束

- **目标规模**：大地图、10000+ 树木、100+ 工人、建筑/道路/农田系统
- **核心架构**：Terrain（渲染） → WorldData → WorldGrid → ChunkManager → A* → Job → Worker → ViewPool
- **核心原则**：数据与表现分离；Terrain 只负责渲染；Grid 负责世界逻辑；A* 只负责寻路；GameObject 仅用于表现
- **性能目标**：TreeView ≤ 500、Worker ≤ 100、CPU < 10ms、GPU < 8ms
- **技术选型**：Unity 2022.3 LTS / Built-in Render Pipeline / New Input System；暂不引入 DOTS/ECS

## 最小可玩里程碑

完成以下任务即可得到一个可运行、可交互的原型：
0.1 → 0.2 → 1.1 → 1.2 → 1.3 → 1.4 → 1.5 → 2.1 → 2.2 → 2.3 → 2.4 → 2.5 → 2.6 → 3.1 → 3.2 → 3.3 → 3.4 → 3.5 → 3.6 → 5.1 → 5.2 → 5.3 → 5.9

**可验证行为**：
- 斜 45° 相机漫游大地图
- 近处树木以 GameObject View 显示，远处回归 Terrain
- 可生成工人
- 可标记树木砍伐
- 工人自动寻路到树、砍伐、树木从世界中移除

## 关键早期决策

1. **坐标约定**：GridPos 原点与世界原点关系，高度 Y 由 Terrain 采样还是 Cell 存储
2. **Chunk 尺寸**：默认 32×32，需在 3×3 激活窗口下验证性能预算
3. **寻路图表示**：稠密网格图（简单、内存大）还是稀疏节点图（复杂、内存小）
4. **Entity ID 类型**：统一使用 `int`/`uint`，0 表示空
5. **系统通信方式**：C# 事件、事件总线或直接引用
6. **序列化格式**：JSON（可调试）或 Binary（体积小）
7. **Terrain 所有权**：Terrain 仅在启动时是树木位置权威，运行时权威为 WorldData
8. **Tick 频率与确定性**：固定模拟 Tick，避免可变频率导致运动和存档不一致

## 风险与缓解

| 风险 | 影响 | 缓解 |
|------|------|------|
| 10000+ Terrain TreeInstance 运行时编辑开销 | 高 | 仅将 Terrain 用作远处 LOD，活跃树用 GameObject |
| 100 工人同时 A* | CPU 峰值 | 按帧分摊、缓存路径、局部 Graph Update |
| Chunk 边界对象池抖动 | 帧率尖刺 | 增加滞后/惰性停用、预生成池 |
| 热点路径 GC 分配 | CPU 超标 | 池化集合、使用 struct、避免 LINQ/闭包 |
| 500+ View + 建筑 + 工人 Draw Call | GPU 超标 | GPU Instancing、LOD、材质合并 |
| 多格建筑碰撞 | 逻辑错误 | 为 footprint 重叠和 Graph Update 写单元测试 |
| 存档版本不兼容 | 迭代破坏旧档 | 保存格式从第一天起带版本号 |

## 验证与验收

### 阶段验收
- 每个 Phase 完成后，在 Play Mode 中运行对应场景的 smoke test
- 使用 Unity Profiler 确认该阶段无异常 GC 分配或 CPU 尖刺

### 最终验收
- 在目标硬件上运行完整场景：10000+ 树、100 工人、3×3 Chunk
- 持续运行 5 分钟后平均 CPU < 10ms、GPU < 8ms
- 保存 → 退出 → 读取后世界状态一致
- 玩家可完成砍树、建造、铺路、农田、搬运五种核心操作
